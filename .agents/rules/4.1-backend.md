# 4.1 — Backend Rules

## Purpose

Define standards for backend API development using Fastify, Prisma, PostgreSQL, and supporting libraries.

## Stack (AUTHORITATIVE)

| Concern | Library | Notes |
|---------|---------|-------|
| Framework | Fastify | Typed, plugin-based, high-performance |
| Language | TypeScript (strict) | `any` FORBIDDEN |
| Validation | Zod | Input AND output validation |
| ORM | Prisma | Database access layer |
| Database | PostgreSQL | Primary data store |
| Auth | jose (JWT) + argon2 (password) | See 8.1-security.md |
| Logging | Pino | Structured logging (built into Fastify) |
| IDs | nanoid or cuid2 | Sequential/guessable IDs FORBIDDEN |
| Cache | Redis | [STANDARD] For caching + rate limiting |
| Queue | BullMQ + Redis | [STANDARD] For background jobs |
| API Docs | fastify-swagger + fastify-swagger-ui | Auto-generated from Zod |

## Architecture Pattern (ABSOLUTE)

```
Request → Controller → Service → Repository → Database
                ↓
           Validation (Zod)
```

- **Controllers**: thin — validate input, call service, return response
- **Services**: business logic, orchestrate repositories, enforce rules
- **Repositories**: database access ONLY (Prisma queries)
- DB access in controllers FORBIDDEN
- Business logic in repositories FORBIDDEN
- Direct Prisma calls outside repositories FORBIDDEN

## API Design (ABSOLUTE)

- API versioning REQUIRED: `/api/v1/...`
- RESTful conventions REQUIRED
- Pagination REQUIRED: default 20, max 100
- Max file size: 400 LOC — split if exceeded

### Input/Output Contracts

- Every endpoint MUST validate request input with Zod
- Every endpoint MUST validate response output with Zod
- "Best-effort" validation FORBIDDEN
- Implicit trust in client input FORBIDDEN
- Mass assignment FORBIDDEN — explicit DTO allowlist REQUIRED

### Error Responses

- Errors MUST follow a standard shape:

```typescript
interface ApiError {
  statusCode: number
  error: string
  message: string           // user-safe message
  errorCode: string         // stable machine-readable code
  requestId: string         // correlation
}
```

- Error messages MUST NOT reveal: resource existence, authorization logic, internal identifiers
- Internal errors MUST return generic 500 with `requestId`
- [STANDARD] Unauthorized access MUST return generic 404 (not 403) — Non-Leak Rule

## API Documentation (AUTHORITATIVE)

- OpenAPI v3.0+ REQUIRED
- fastify-swagger REQUIRED — auto-generated from Zod schemas
- Manual OpenAPI YAML editing FORBIDDEN
- All routes MUST have: summary, request schema, response schema, tags

### Visibility

- `/documentation` + `/openapi.json`: allowed in development/staging
- Production: DISABLED by default
- [STANDARD] Production exception: admin auth + IP allowlist + audit logging

## Database — Prisma (ABSOLUTE)

- Prisma ONLY for database access
- Manual SQL changes FORBIDDEN (use migrations)
- UTC timestamps ONLY
- Currency as integers ONLY (cents, not dollars)
- Soft delete as default (add `deletedAt` column)
- Transactions REQUIRED for multi-table writes

### DB Safety

- Connection pooling REQUIRED
- [STANDARD] Query budgets REQUIRED for hot endpoints
- Index REQUIRED for every query path
- [STANDARD] Cursor pagination REQUIRED for high-cardinality lists (offset OK for small sets)
- Migration safety: expand/contract pattern only

### Destructive Operations

- `DROP COLUMN` / `DROP TABLE` FORBIDDEN in automated migrations if data exists
- Data backfill scripts REQUIRED for new non-nullable columns
- Raw SQL FORBIDDEN unless wrapped in transaction with explicit rollback

## Logging & Observability (ABSOLUTE)

- Structured logging REQUIRED (Pino)
- Global error handler REQUIRED
- `requestId` REQUIRED on every request

### Required Log Fields

- `service`, `env`, `version`
- `requestId`
- `route`, `statusCode`, `latencyMs`
- [STANDARD] `tenantId`, `userId` (pseudonymous)
- [STANDARD] `jobId` (for background jobs, correlated with `requestId`)

### Redaction REQUIRED

- Secrets, tokens, credentials
- Full PII (log pseudonymous IDs only)
- Webhook payloads (store hash/ids only)

### [STANDARD] Tracing

- OpenTelemetry RECOMMENDED for mid-size+ projects
- High-cardinality attributes FORBIDDEN
- Large payloads in logs/traces FORBIDDEN

### [SCALE] Metrics & Alerts

- Metrics: API latency p95/p99, error rate, queue depth, worker CPU/RAM
- Alerts: queue stuck, failure spike, disk below threshold

## Scale & Failure Controls (AUTHORITATIVE)

- Timeouts REQUIRED for ALL I/O (DB, Redis, HTTP, external APIs)
- [STANDARD] Circuit breaker + bounded retries REQUIRED for external dependencies
- Retries MUST be bounded by: max attempts + max elapsed time
- Retry non-idempotent operations FORBIDDEN

### [STANDARD] Backpressure

- DB overloaded → shed load / return 503
- Queue too deep → pause enqueue / reject new work

### [STANDARD] Rate Limiting

- Rate limiting REQUIRED (per user; IP-only FORBIDDEN)
- Rate limiting MUST fail-closed for auth endpoints if Redis is unavailable

## [STANDARD] Background Jobs — BullMQ (AUTHORITATIVE)

Only if project requires background processing:

- Jobs MUST be idempotent
- Idempotency key REQUIRED: `jobType:resourceId:inputHash`
- Retry, backoff, timeout REQUIRED
- Dead-letter queue REQUIRED
- `requestId` REQUIRED in job payloads (correlation)

### Redis Degradation

- Redis down → enqueue MUST fail-closed for irreversible work
- API MUST return 503 (safe failure)
- Silent enqueue failures FORBIDDEN

## [STANDARD] Caching — Redis (AUTHORITATIVE)

Only if project uses caching:

- TTL REQUIRED for all cache keys
- Invalidate on mutation REQUIRED
- [SCALE] Cache stampede protection REQUIRED
- User-specific data MUST NOT be cached at CDN

## Webhooks (AUTHORITATIVE)

Only if project receives webhooks:

- Signature verification REQUIRED
- Timestamp verification REQUIRED
- Replay protection REQUIRED
- Idempotency REQUIRED
- Webhook payloads MUST NOT be logged (store hash/ids only)
