# 6.1 — Fullstack Integration

## Purpose

Define rules for integrating frontend, backend, and mobile when they coexist in the same project — especially monorepo patterns, shared packages, and API contracts.

## When This Applies

This file applies ONLY when:

- Profile FB (Frontend + Backend)
- Profile MB (Mobile + Backend)
- Profile FBM (Fullstack + Mobile)
- Any project where frontend/mobile consumes a custom backend API

Skip this file for Frontend-only, Mobile-only, or Supabase-only projects.

## Monorepo Setup (AUTHORITATIVE)

- pnpm workspaces REQUIRED
- Workspace definition in `pnpm-workspace.yaml`:

```yaml
packages:
  - 'apps/*'
  - 'packages/*'
```

- Root `package.json` MUST NOT contain app-specific dependencies
- Each app and package MUST have its own `package.json`

## Shared Packages (AUTHORITATIVE)

### Standard Packages

| Package | Purpose | Required? |
|---------|---------|-----------|
| `packages/shared` | Shared types, constants, Zod schemas | REQUIRED (FB/FBM) |
| `packages/database` | Prisma client + schema | REQUIRED if multiple apps need DB |
| `packages/config` | Shared config types | [STANDARD] RECOMMENDED |
| `packages/ui-kit` | Shared UI components | [STANDARD] RECOMMENDED (FBM with web+mobile) |

### Package Rules

- Every package MUST have `src/index.ts` as the ONLY public entry point
- Packages MUST NOT load dotenv or read `process.env` at import time
- Packages MUST NOT have side effects on import
- Import via `@pkg/[name]` REQUIRED — relative cross-package imports FORBIDDEN
- Packages MUST NOT contain business logic — only shared utilities and types

## API Contract (ABSOLUTE)

### Type Sharing Strategy

Frontend and mobile MUST consume the same API types as the backend produces.

**Preferred approach — Shared Zod schemas:**

```
packages/shared/
└── src/
    ├── schemas/
    │   ├── user.schema.ts      # Zod schemas
    │   ├── auth.schema.ts
    │   └── index.ts
    ├── types/
    │   ├── user.types.ts       # Inferred from Zod: z.infer<typeof UserSchema>
    │   └── index.ts
    └── index.ts
```

- Zod schemas defined ONCE in shared package
- Backend uses schemas for validation
- Frontend/mobile uses schemas for response parsing
- Types are inferred from Zod schemas — no manual type duplication

### API Client

```
packages/shared/ (or packages/api-client/)
└── src/
    └── api/
        ├── client.ts           # configured HTTP client (ky/fetch wrapper)
        ├── endpoints/
        │   ├── users.ts        # typed API functions
        │   └── auth.ts
        └── index.ts
```

- API client functions MUST return typed responses
- Frontend/mobile MUST use the shared API client
- Direct `fetch()` in frontend/mobile FORBIDDEN

## Environment Variables (AUTHORITATIVE)

### Monorepo .env Strategy

```
root/
├── .env                        # shared infra (compose ports, DB URL for dev) — NO secrets
├── apps/
│   ├── api/.env                # API secrets (JWT key, etc.)
│   ├── web/.env                # web env (ONLY public vars)
│   └── mobile/.env             # mobile env
```

- Root `.env` MUST NOT contain application secrets
- Each app MUST use app-scoped env
- Web env MUST use explicit public prefix (`VITE_*`, `NEXT_PUBLIC_*`)
- Non-public vars MUST NOT be accessible in client bundle
- Packages MUST NOT load dotenv

## Database Access (AUTHORITATIVE)

In monorepo (Profile FBM):

- Prisma schema lives in `packages/database/prisma/schema.prisma`
- All apps import DB via `@pkg/database`
- `apps/api/prisma/` FORBIDDEN in monorepo
- `apps/worker/prisma/` FORBIDDEN in monorepo

## CI for Monorepo (AUTHORITATIVE)

[STANDARD] CI MUST run on every push & PR:

- `pnpm -r lint` (all packages)
- `pnpm -r typecheck` (all packages)
- `pnpm -r test` (all packages)
- Per-app build verification

[STANDARD] Changes to `packages/*` MUST trigger CI for all consuming apps.

## Development Workflow (AUTHORITATIVE)

Root scripts for local development:

```json
{
  "dev": "pnpm -r --parallel dev",
  "api": "pnpm --filter api dev",
  "web": "pnpm --filter web dev",
  "mobile": "pnpm --filter mobile start",
  "build": "pnpm -r build",
  "lint": "pnpm -r lint",
  "typecheck": "pnpm -r typecheck",
  "test": "pnpm -r test"
}
```

- `pnpm dev` MUST start all services needed for local development
- Each app MUST be independently runnable via its own script
