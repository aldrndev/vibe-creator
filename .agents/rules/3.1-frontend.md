# 3.1 — Frontend Rules

## Purpose

Define standards for frontend development using React ecosystem: Next.js, Vite, Tanstack, and supporting libraries.

## Stack (AUTHORITATIVE)

| Concern | Library | Notes |
|---------|---------|-------|
| Framework | Next.js or Vite + React | Next.js for SSR/SEO; Vite for SPA |
| Language | TypeScript (strict) | `any` FORBIDDEN |
| Server State | Tanstack Query (React Query) | ALL async data |
| Client State | Zustand | Slice-based stores |
| Routing (Vite) | Tanstack Router | Type-safe routing for Vite projects |
| Routing (Next.js) | App Router (built-in) | Use Next.js conventions |
| Forms | React Hook Form + Zod | Schema-first validation |
| Styling | Tailwind CSS | With semantic CSS variables |
| UI Primitives | shadcn/ui | Accessible, styled primitives |
| Tables | Tanstack Table | For complex data tables |
| Validation | Zod | Source of truth for all schemas |
| HTTP Client | ky or fetch wrapper | Direct fetch calls FORBIDDEN |
| Animation | Framer Motion | Layout animations, gestures, transitions |
| Icons | Lucide React | Tree-shakable, consistent icon set |
| Class Merge | clsx + tailwind-merge | Conditional classes without conflicts |
| Date | date-fns | Lightweight, tree-shakable date utils |
| Theme | next-themes | Next.js only — dark mode, system theme |
| URL State | nuqs | Next.js only — type-safe URL search params |

### Library Selection Rules

- Direct `fetch()` calls in components FORBIDDEN — use Tanstack Query
- Global state for server data FORBIDDEN — use Tanstack Query
- CSS-in-JS runtime libraries FORBIDDEN (styled-components, emotion) — use Tailwind
- jQuery or DOM manipulation libraries FORBIDDEN
- Moment.js FORBIDDEN — use `date-fns` or `dayjs`

## Component Rules (ABSOLUTE)

- Max component size: 500 LOC — split if exceeded
- Error boundaries REQUIRED for route-level failures
- Suspense REQUIRED for lazy-loaded routes and async components
- Stable `key` props REQUIRED for lists
- Named exports ONLY — default exports FORBIDDEN (except Next.js pages where required)

### Component Structure

```typescript
// 1. Imports
import { useState } from 'react'

// 2. Types
interface UserCardProps {
  user: User
  onSelect: (id: string) => void
}

// 3. Component
export function UserCard({ user, onSelect }: Readonly<UserCardProps>) {
  // hooks first
  const [isExpanded, setIsExpanded] = useState(false)

  // handlers
  const handleClick = () => onSelect(user.id)

  // early returns for edge cases
  if (!user.isActive) return null

  // render
  return (...)
}
```

### Props Immutability (ABSOLUTE)

- Props type MUST be wrapped with `Readonly<>` utility type in function signature
- Direct mutation of props FORBIDDEN — enforced by Biome `noReactPropAssignments`
- Spread props into new objects when modification is needed

```typescript
// ✅ Good — Readonly wrapper
export function UserCard({ user, onSelect }: Readonly<UserCardProps>) { ... }

// ✅ Good — inline readonly
export function Badge({ label, variant = 'default' }: Readonly<{ label: string; variant?: string }>) { ... }

// ❌ Bad — mutable props
export function UserCard({ user, onSelect }: UserCardProps) { ... }

// ❌ Bad — mutating props
export function UserCard(props: Readonly<UserCardProps>) {
  props.user = newUser // Biome error: noReactPropAssignments
}
```

## Data Fetching — Tanstack Query (ABSOLUTE)

- Query keys MUST be stable and deterministic
- `initialData` shortcuts FORBIDDEN — use `placeholderData` if needed
- Manual refetch hacks FORBIDDEN — use `invalidateQueries`
- Mutations MUST invalidate relevant queries on success
- Retry MUST be bounded (max 3) — MUST NOT cause retry storms
- Loading and error states MUST be handled in UI
- [STANDARD] Proper SSR hydration REQUIRED when using Next.js

### Query Key Convention

```typescript
// Use factory pattern for query keys
export const userKeys = {
  all: ['users'] as const,
  lists: () => [...userKeys.all, 'list'] as const,
  list: (filters: UserFilters) => [...userKeys.lists(), filters] as const,
  details: () => [...userKeys.all, 'detail'] as const,
  detail: (id: string) => [...userKeys.details(), id] as const,
}
```

## Client State — Zustand (AUTHORITATIVE)

- Slice-based stores REQUIRED
- Cross-slice direct imports FORBIDDEN — use store composition
- Derived state MUST be computed selectors (no duplicate truth)
- Server state in Zustand FORBIDDEN — use Tanstack Query

```typescript
// ✅ Good - slice-based store
interface AuthSlice {
  user: User | null
  setUser: (user: User | null) => void
}

export const useAuthStore = create<AuthSlice>((set) => ({
  user: null,
  setUser: (user) => set({ user }),
}))
```

## Routing — Tanstack Router (Vite Projects) (AUTHORITATIVE)

- File-based routing REQUIRED
- Type-safe route params REQUIRED
- Route validation with Zod REQUIRED for search params
- Pending/error states MUST be handled per route
- Code-splitting per route REQUIRED

## Forms (ABSOLUTE)

- React Hook Form REQUIRED for complex forms (3+ fields)
- Zod schema as source of truth REQUIRED
- Double-submit protection REQUIRED (disable button during submission)
- Submit handlers MUST be idempotent when possible

### User Feedback Rules

- `window.alert` / `confirm` / `prompt` FORBIDDEN
- Toast notifications: allowed sparingly for non-critical feedback
- Validation errors MUST be field-level (near the input)
- Submit errors MUST be section-level banners (near the form)
- Error messages MUST persist until resolved or dismissed
- Success messages MAY auto-dismiss (bounded duration)

## Styling — Tailwind CSS (AUTHORITATIVE)

- Tailwind with design tokens (CSS variables) REQUIRED
- Inline arbitrary values SHOULD be minimized — use theme config
- `!important` FORBIDDEN
- Component variants: use `class-variance-authority` (cva) or equivalent
- Responsive: mobile-first breakpoint approach

### CSS Property Order — Concentric (AUTHORITATIVE)

When writing raw CSS or `@apply` blocks, properties MUST follow the **Concentric CSS order** (outside-in). This mirrors how the browser renders elements: position → box model → content → visual.

```css
.element {
  /* 1. Generated Content */
  content: '';

  /* 2. Position & Layout */
  position: relative;
  top: 0;
  right: 0;
  bottom: 0;
  left: 0;
  z-index: 1;

  /* 3. Display & Flow */
  display: flex;
  flex-direction: column;
  align-items: center;
  justify-content: center;
  gap: var(--space-4);
  overflow: hidden;

  /* 4. Box Model (outside-in) */
  margin: 0;
  border: 1px solid var(--color-border);
  border-radius: var(--radius-md);
  padding: var(--space-4);
  width: 100%;
  min-width: 0;
  max-width: 600px;
  height: auto;

  /* 5. Typography */
  color: var(--color-text);
  font-family: var(--font-family-sans);
  font-size: var(--font-size-base);
  font-weight: 400;
  line-height: 1.5;
  text-align: left;
  text-decoration: none;
  white-space: nowrap;

  /* 6. Visual & Decorative */
  background: var(--color-surface);
  box-shadow: var(--shadow-sm);
  opacity: 1;

  /* 7. Transform & Animation */
  transform: translateY(0);
  transition: all 150ms ease-out;
  animation: none;

  /* 8. Interaction */
  cursor: pointer;
  pointer-events: auto;
  user-select: none;
}
```

**Tailwind Class Order:**

When writing Tailwind classes, follow the same concentric order for class arrangement:

```tsx
// ✅ Good — concentric order in Tailwind classes
<div className="
  relative z-10                          {/* position */}
  flex flex-col items-center gap-4       {/* display & flow */}
  m-0 border rounded-md p-4 w-full      {/* box model */}
  text-gray-900 text-base font-medium   {/* typography */}
  bg-white shadow-sm                     {/* visual */}
  transition-all duration-150            {/* animation */}
  cursor-pointer                         {/* interaction */}
"/>

// ❌ Bad — random order
<div className="bg-white cursor-pointer p-4 flex text-base relative shadow-sm"/>
```

- AI MUST follow this order when writing new CSS or Tailwind classes
- AI SHOULD reorder existing CSS properties to match when modifying a file
- Exceptions allowed for one-line utility classes (e.g., `className="flex items-center gap-2"`)

## Modern Web Platform (ABSOLUTE)

AI MUST prefer native web platform features over JavaScript libraries when available. This prevents bloated, outdated code and produces UI that feels native and premium.

### CSS Layout — Modern First

- Container Queries PREFERRED over media queries for component-level responsiveness
- CSS `:has()` PREFERRED over JavaScript for conditional parent styling
- CSS Subgrid PREFERRED over nested flexbox for aligned grid layouts
- `content-visibility: auto` REQUIRED on long-scrolling page sections for rendering performance

### CSS Animation — Native First

- CSS `@starting-style` + `transition-behavior: allow-discrete` REQUIRED for dialog/popover entry/exit animations
- CSS scroll-driven animations PREFERRED over JS scroll event listeners for parallax/reveal effects
- View Transitions API PREFERRED over Framer Motion `AnimatePresence` for page transitions (Next.js/Vite)
- `interpolate-size: allow-keywords` PREFERRED for animating to/from `auto` height (accordion, collapsible)
- Framer Motion: use ONLY for complex gesture-driven animations that CSS cannot achieve

### HTML Native Components

- `<dialog>` REQUIRED for modals — custom modal implementations FORBIDDEN unless dialog is insufficient
- Popover API (`popover` attribute) PREFERRED over custom dropdown/tooltip implementations
- `inert` attribute REQUIRED on background content when modal/dialog is open
- Customizable `<select>` PREFERRED over custom dropdown libraries (when browser support allows)

### Typography & Text Polish

- `text-wrap: balance` REQUIRED on headings and short text blocks
- `text-wrap: pretty` RECOMMENDED on paragraph body text
- Fallback: wrap in `@supports (text-wrap: balance) {}` if targeting older browsers

### Form UX

- `:user-invalid` / `:user-valid` PREFERRED over `:invalid` / `:valid` for validation styling — shows errors only after user interaction
- `field-sizing: content` RECOMMENDED for auto-sizing textareas
- `enterkeyhint` REQUIRED on mobile-facing form inputs (search, send, go, next)
- `accent-color` REQUIRED to match native form controls (checkboxes, radios, range) with design tokens

### Color & Theming

- `oklch()` RECOMMENDED over `hsl()` for color definitions — perceptually uniform, better for palette generation
- `light-dark()` function RECOMMENDED for dual-theme color values
- `color-scheme: light dark` REQUIRED on `:root` for proper dark mode support
- `scrollbar-color` + `scrollbar-width` REQUIRED for themed scrollbars in dark mode and custom themes

## UI Primitives — shadcn/ui (AUTHORITATIVE)

- shadcn/ui as base primitives (built on Radix internally)
- Prebuilt external UI kits FORBIDDEN unless team-owned
- Components MUST be accessible out of the box
- Customization via Tailwind classes / CSS variables

## Performance (AUTHORITATIVE)

- Core Web Vitals REQUIRED:
  - CLS ≤ 0.1 (Cumulative Layout Shift)
  - LCP ≤ 2.5s (Largest Contentful Paint)
  - INP ≤ 200ms (Interaction to Next Paint)
- `fetchpriority="high"` REQUIRED on LCP images
- Code-splitting REQUIRED for non-critical routes
- Suspense MUST be used for lazy-loaded routes
- Images MUST use `next/image` (Next.js) or lazy loading (Vite)
- [STANDARD] Bundle size SHOULD be budgeted and tracked

## SEO & i18n (WEB) (AUTHORITATIVE)

- Semantic HTML5 REQUIRED
- Single `<h1>` per page with proper heading hierarchy
- Meta tags: `title`, `description`, `og:*` REQUIRED
- [STANDARD] i18n: use stable translation keys (not full sentences)
- [STANDARD] Support ID + EN with auto-detect and fallback to EN

## Next.js Specific (AUTHORITATIVE)

- App Router preferred over Pages Router for new projects
- RSC caching MUST NOT be relied upon for correctness
- `loading.tsx` is lifecycle helper, not UX design
- Experimental flags MUST NOT define core behavior
- Server Actions: use for mutations, validate with Zod
- `"use client"` MUST be explicit and minimized

## Error Handling (ABSOLUTE)

- Error boundaries REQUIRED for route-level failures
- Global fallback UI MUST be accessible and informative
- User-visible errors MUST NOT leak internal details
- [STANDARD] `requestId` SHOULD be shown in a copyable element for support
